## 1. โครงเฟส (Phase Gate)

เฟสตัดสินจาก **follower ปัจจุบัน** เท่านั้น **ไม่ผูกกับจำนวนคลิป**

| Gate | Milestone |
|------|-----------|
| เฟส 1 | 0 → 10,000 (ผ่าน beat 1K ระหว่างทาง) |
| เฟส 2 | 10,000 → 100,000 |
| เฟส 3 | 100,000 → 1,000,000 |

- Milestone canon: **1K → 10K → 100K → 1M** (absolute) — timeline % เป็นแค่ story beat
- ต้องถึง gate ก่อน story event เฟสถัดไปถึง unlock
- **ยกเลิกแล้ว:** แนวคิด "150 คลิป / เฟส 1 = 10 คลิป / เฟส 2 = 40 / เฟส 3 = 45"
  (เก็บไว้เป็น reference ตอน playtest เท่านั้น ไม่เขียนลงเกม)
- **ยกเลิกแล้ว:** limit คลิปต่อวัน (MAX_CLIPS_PER_DAY) — ไม่จำเป็นหลัง Bad End 1 เป็น optional

**แอปบนจอคอมที่ต้องรอเฟส (lock 12 ส.ค. 2569, user):** เฟส 1 มีแค่ **Shop / Editor / Upload / Feedback** (4 ตัว) —
**Bank กับ Message (Inbox) ซ่อนไอคอนไว้ก่อน** โผล่ตอนเข้าเฟส 2 พร้อมกัน (ครบ 6 ตัว)
- `Config.AppMinPhase = { bank = 2, message = 2 }` — `Formulas.appUnlocked(phase, id)` อ่านค่านี้ ไอคอนที่ไม่มีชื่ออยู่ = เข้าได้ตั้งแต่เฟส 1 เสมอ
- ซ่อนฝั่ง client (icon) + เช็คซ้ำฝั่ง server: `MoneyService.adjustSpending` (Bank ⊖⊕) ปฏิเสธถ้า `state.phase < 2` แม้ client จะพยายามยิง action ตรงๆ ก็ตาม (defense-in-depth เหมือน `MentalService.introducedInPhase`/`SponsorService.SponsorOfferMinPhase`)
- Manage (จ้างพนักงาน, §9.8) ไม่ต้องเพิ่ม gate เอง — เข้าได้ทางเดียวคือปุ่มในแอป Bank ซึ่งซ่อนอยู่แล้ว และ roster ทุกแถวก็ล็อก `phase >= 2` อยู่แล้วเดิม (§9.8)

## 2. สูตร Follower ต่อคลิป

```
follower ที่ได้ = เลขสุ่ม base ของเฟส × VidQ multiplier × mental multiplier
                  แล้วมีโอกาส 12% ได้ viral spike ×4–8
```

**Base ต่อเฟส (สุ่ม):**

| เฟส | base |
|-----|------|
| 1 | 400 – 900 |
| 2 | 1,400 – 2,600 |
| 3 | 9,000 – 15,000 |

**VidQ multiplier** (จาก accuracy มินิเกมตัดคลิป เต็ม 200):

| Tier | Accuracy | Multiplier |
|------|----------|-----------|
| C | 0 – 50 | ×0.5 |
| B | 51 – 100 | ×1 |
| A | 101 – 150 | ×1.5 |
| S | 151 – 200 | ×2 |

> ใช้ label **C/B/A/S ทุกหน้า** — เลิกใช้ bad/normal/good/awesome แล้ว

**Edit more — lock 27 ก.ค.:** จอสรุป QTE มีปุ่ม `Edit more` = ตัด**คลิปใหม่**ต่อทันที ไม่ต้องออกไปเปิดแอปใหม่
เป็นปุ่มลัดล้วนๆ **ไม่ใช่การตัดคลิปเดิมซ้ำ** — คะแนนของแต่ละคลิปแยกกัน ตัดแล้วตัดเลย
ทุกรอบเสีย **ใจ −20 + นับ "ตัดคลิป 5 ติด"** ตามปกติ · ไม่มี cap จำนวนรอบ เพราะ mental คือ limit อยู่แล้ว

**Viral system:** ทุกคลิปมีโอกาส 12% → follower ×4 ถึง ×8 (สุ่ม)
ต้องมี VFX/SFX + popup "ไวรัลแล้ว!" ตอน trigger

## 3. Mental Bar

**Multiplier 3 โซน:**

| โซน | ผล |
|-----|-----|
| 70 – 100% | follower ×1.0 – ×1.25 (ยิ่งใกล้ 100 โอกาสได้โบนัสยิ่งสูง) |
| 40 – 69% | ปกติ ×1.0 |
| 1 – 39% | follower ×0.6 – ×1.0 (ยิ่งใกล้ 0 ยิ่งหักหนัก) |
| 0% | **Bad End ②** |

> Cap ที่ ×1.25 จงใจ — ไม่ให้ stack กับ viral (×4–8) + S tier (×2) จน pacing พัง

**ค่าเริ่มต้น:** 80% | **ลดตามธรรมชาติ:** 1% ทุก 4.5 วินาที
**ระบบ introduce ตอน:** phase 2

**สิ่งที่ลด mental:**
- ตัดคลิป −20
- เลือกข้อคุยกับ NPC แย่ −10
- เลือกข้อตอบ comment แย่ −5
- จ่ายค่าเช่าไม่ทัน −15

**สิ่งที่เพิ่ม mental:**
- เลือกข้อคุยกับ NPC ดี +15
- เลือกข้อตอบ comment ดี +10
- คลิปไวรัล +25
- Activity พ่อนคลาย: ออกกำลังกาย +30 / พักผ่อน +40 / กินข้าว +20 (แก้ 9 ส.ค. — เดิม +20/+25/+15)

**Drain/Recovery Modifiers (lock 19 ก.ค. — user ตัดสิน):**

ความหมาย: ฝั่ง drain = คูณอัตรา drain | ฝั่งดี = **คูณ delta ฝั่งบวก** (ฟื้นแรงขึ้น)
ซ้อนกัน = คูณกันหมด **cap ที่ ×3** ทั้งสองฝั่ง

| Modifier | คูณ | ติดเมื่อ | หายเมื่อ |
|----------|-----|---------|---------|
| อดนอน | ×1.5 drain | ตื่นต่อเนื่องครบ 20 ชม.เกม | นอน |
| Canon event | ×1.25 drain | milestone event trigger | ครบ 1 วันเกม (24 ชม.) |
| ตัดคลิป 5 ติด | ×1.5 drain | ตัดคลิป 5 อันโดยไม่ทำ activity คั่น | ทำ activity |
| comment แย่ 3 ติด | ×2 drain | ตอบ ⊖ 3 ครั้งติด | activity หรือตอบ ⊕ |
| comment ดี 3 ติด | ×1.25 recovery | ตอบ ⊕ 3 ครั้งติด | ครบ 1 วันเกม |
| viral 2 วันติด | ×2 recovery | คลิป viral สองวันติดกัน | ครบ 1.5 วันเกม (36 ชม.) |

> **Dormant (อยู่ใน config แต่ไม่ wire):** "คุย NPC แย่/ดี 3 ติด" — ขัดกับ §6/§7 ที่ lock ว่า
> dialogue ทางเดียวไม่มี choice จึงไม่มีทาง trigger — เก็บไว้เผื่อดึง NPC choice กลับจาก backlog

## 4. Economy

**เงินต่อคลิป:**
```
เงิน = follower ที่ได้จากคลิปนั้น × อัตราหาเงิน
```

| เฟส | rate (บาท/follower) |
|-----|---------------------|
| 1 | 0.8 |
| 2 | 1.2 |
| 3 | 1.5 |

**ค่าใช้จ่าย — รอบรายสัปดาห์ในเกม (7 วัน) ไม่นับคลิป:**

| เฟส | ค่าเช่า | เน็ต | ค่ากิน | รวม/สัปดาห์ |
|-----|---------|------|--------|-------------|
| 1 | 1,500 | 300 | 400 | ~2,200 |
| 2 | 3,000 | 500 | 600 | ~4,100 |
| 3 | 6,000 | 800 | 900 | ~7,700 |

**Upgrade cost — ตารางเต็มย้ายไป §9.5** (เคยขยายเป็น 15 ระดับ 28 ก.ค. ตัดกลับเหลือ 6 เมื่อ 12 ส.ค. · **2 สาย: กล้อง / ที่เก็บ** — สายคอมพิวเตอร์ตัดถาวร 11 ส.ค. ดู §9.5)
- 5 ขั้นแรกของกล้อง: 2,000 / 8,000 / 30,000 / 120,000 / 300,000 — **ล็อก ห้ามขยับ**
- 5 ขั้นแรกของที่เก็บ: 1,500 / 6,000 / 25,000 / 100,000 / 250,000 — **ล็อก ห้ามขยับ**

> ⚠️ **เพดานเงินทั้งเกม** = `10K×0.8 + 90K×1.2 + 900K×1.5 ≈ 1.47 ล้าน` (หักรายจ่ายเหลือ ~1.3 ล้าน)
> ตัวเลขนี้คือกรอบที่ราคา upgrade ทุกสายต้องอยู่ในนั้น — ดูผลกระทบเต็มใน §9.5

~~Upgrade ดันความชัด → ดัน VidQ multiplier~~ — **ผิด แก้ 26 ก.ค.**: กล้องคูณแค่ GB/คลิกตอนอัด **ไม่แตะ VidQ** (VidQ มาจาก QTE อย่างเดียว) loop เศรษฐกิจปิดที่ อัดไว → ตัดได้บ่อย → follower/เงินเข้าเร็ว

**Sponsor** — ⚠️ **แก้ดีไซน์ 9 ส.ค. 2569 (user)**: เลิกวางลงปฏิทิน เปลี่ยนเป็น notification กดรับ
- ปลดล็อค 10K follower + เฟส 2 ขึ้นไป · offer สุ่มเด้งเอง 5%/วัน (เงื่อนไขเดิม ไม่ขยับ)

- ~~จ่ายเป็นเงินก้อน~~ · ~~Trade-off: วันถ่าย sponsor ไม่ได้ปั๊ม follower~~ — **ตัดทั้งคู่**

## 5. Endings (6 แบบ)

### Bad End Variants

| # | เงื่อนไข | Phase | หมายเหตุ |
|---|----------|-------|----------|
| ① | เงินไม่พอ โดนไล่ที่ 2 รอบ → กลับบ้าน โดนด่า → กลับไปเป็นทาสตลาดแรงงาน | 1, 2 | **Optional** — ต้องจงใจเล่นให้เงินหมด |
| ② | mental ≤ 0% → เก็บตัว เลิกทำ หายไปจากวงการ | 2, 3 | **Optional** — ต้องจงใจไม่ฟื้นใจ |
| ③ | choices ⊖ เยอะเกิน → โดนสังคมแบน/cancel หายจากวงการ | 3 | |

**สำคัญ — Roblox compliance:** ห้ามมีเนื้อหาฆ่าตัวตาย/ลอบฆ่าเด็ดขาด
ทั้ง ② และ ③ reframe เป็น **ความล้มเหลวเชิงสังคม/อาชีพ** ไม่ใช่ความตาย
(ถ้าไม่แก้ = เกมโดน moderate/ลบ = ส่งลิงก์ไม่ได้ = ตกรอบ)

**Bad ① vs ② ต่างกันชัด:** ① = แพ้เพราะปัจจัยภายนอก (เงิน) | ② = แพ้เพราะปัจจัยภายใน (ใจ)

### Trigger Conditions (ฉบับ %)

VidQ tier % = สัดส่วนของคลิปที่ถ่ายจริงทั้งหมด
Choices % = สัดส่วนของ choice ที่ตอบไปทั้งหมด (⊕ + ◎ + ⊖ = 100%)

| Ending | เงื่อนไข |
|--------|----------|
| **Bad ③** | `C ≥ 33% && B ≤ 33%` **\|\|** `⊖ ≥ 50% && ◎ ≤ 25%` |
| **Neutral ①** | `C ≤ 20% && B ≤ 33% && A ≥ 13% && S ≤ 13%` **\|\|** `\|⊖ − ⊕\| + ◎ < 25%` |
| **Neutral ②** | `C ≤ 26% && B ≤ 33%` **\|\|** `⊖ ≤ 37.5% && ◎ ≥ 25%` |
| **Good ①** | `C ≤ 16% && B ≤ 33% && A ≥ 30% && S ≤ 20%` **&&** `⊕ ≥ 62.5% && ⊖ ≤ 12.5% && ◎ ≤ 12.5%` |

**Priority order สำคัญ** — เช็คจากแย่สุด → ดีสุด, return ทันทีที่ match:
`Bad ① (เงิน) → Bad ② (mental) → Bad ③ → Good ① → Neutral ① → Neutral ②`
(ไม่งั้นเงื่อนไข overlap กันแล้ว trigger มั่ว)

**หมายเหตุ Good ①:** `⊕ ≥ 62.5%` ไม่ใช่เพดานจริง — เพราะ ⊖ ≤ 12.5% และ ◎ ≤ 12.5% บีบให้ ⊕ ต้อง ≥ 75% จริงๆ

**เลข .5:** เก็บไว้ในเอกสารออกแบบ (แม่นยำ) | สไลด์นำเสนอปัดกลมได้ (50/38/25/13/63)

**Neutral/Good ต้องถึง 1M ก่อน** — Bad End คือทางที่ไม่ถึง

**Endgame flow (จาก timeline):** 1M follower → งาน **BCA (Best Creator Award)** → cutscene → กลับไปหาพ่อแม่

## 9.5 ระบบอัดคลิป + อุปกรณ์ 6 ระดับ (lock 21 ก.ค. · ขยาย 6→15 เมื่อ 28 ก.ค. 2569 · **ตัดกลับเหลือ 6 เมื่อ 12 ส.ค. 2569 (user)**)

> **ระดับ 1-6 = ของเดิมที่ล็อกไว้ 21 ก.ค. ไม่ขยับสักตัว** (ราคา/GB/resolution) — มีเทสยืนยันใน `RunTests` ห้ามแก้

→ อัตราส่วนนี้คงที่ทุกระดับที่ขายจริง (1-6) มีเทสวนเช็ค ถ้าเพิ่มระดับใหม่ต้องรักษาอัตราส่วนนี้

> ### 💰 เพดานเงิน — ยังมี balance hole ที่ไม่ได้ปิด
>
> เงินทั้งเกมมีเพดานตายตัวจาก §4: `10K×0.8 + 90K×1.2 + 900K×1.5 ≈ 1.47 ล้าน` หักค่าใช้จ่ายรายสัปดาห์เหลือ **~1.3 ล้าน**
> ระดับ 1-6 (สูงสุดที่ซื้อได้ตอนนี้) ของ 2 สายที่เหลือ = กล้อง `460,000` + ที่เก็บ `382,500` = **842,500**
>
> ⚠️ **ยังไม่ปิดช่องว่าง:** เหลือเงินส่วนเกิน ~460,000 ที่ไม่มีอะไรให้ซื้อต่อ (ของกินใช้แล้วหมดดูดไปได้บางส่วน ฿12,000/ครั้ง แต่ไม่ครบ) — ไม่ใช่ blocker ของ deadline แต่ user ควรรู้ว่าไม่มี "เป้าให้ไปต่อ" เหลือแล้วหลังตัดระดับ 7-15 ออก (เดิมระดับ 7-15 ทำหน้าที่นั้น)
> ถ้าอยากปิดช่องนี้ในอนาคต: ขยับราคาระดับ 5-6 ขึ้น / ลดเพดานเงิน / หาของใหม่มาดูดเงินส่วนเกิน

**🥤 ของกินใช้แล้วหมด — เครื่องดื่มชูกำลัง (เพิ่ม 11 ส.ค. 2569 · user · `Config.Consumables`)**
ซื้อที่ **แอป Shop บนคอม** (แถวล่างสุด แยกจากบันไดอัปเกรด) — **ซื้อ = ดื่มทันที ไม่มีคลังของ** (ไม่ต้องมี inventory UI + กันตุนแล้วซดรวดเดียว)

| ค่า | ตัวเลข | เหตุผล |
|---|---|---|
| ราคา | ฿12,000 | money sink ของเฟส 2+ · เฟส 1 ทั้งเฟสได้ ~8,000 = จงใจซื้อไม่ไหว |
| ฤทธิ์ | 1 วันในเกม (24 ชม.) | ≈ 3 นาทีจริง (`secondsPerGameHour` 7.5) — ดื่มที่คอมแล้วออกไปอัด |
| ผล | โซน Perfect **×2** · โซน Good **×1.5** | QTE เท่าเดิม แต่กดติดง่ายขึ้น = ได้ footage เยอะขึ้นจริง |
| หมดฤทธิ์ | ใจ **−8** | อาการ crash — ทางลัดต้องมีต้นทุน (thesis เดียวกับ Bank §9.7) |

**⚠️ ทำไมไม่เพิ่ม "โอกาสเกิด QTE" ตามที่คิดตอนแรก:** QTE คือ **lockout** (freeze เดิน + ปิด E) คำนวณจากค่าจริง —
คลิก cooldown 0.6 วิ · QTE เฉลี่ย ~4.5 วิ → **%เวลาที่ติดอยู่ใน QTE = `4.5 / (4.5 + 0.6/chance)`**
`chance` 2% = **13%** · 10% (ปัจจุบัน) = **43%** · 30% (ถ้า ×3) = **69%** → กลายเป็นเกมยืนกด Space แทนที่จะได้เดินอัดคลิป
เพิ่มความถี่ = ให้ผลตรงข้ามกับที่ตั้งใจ เลยเปลี่ยนเป็น "โซนกว้างขึ้น" แทน — **นี่คือไอเดีย "QTE window กว้างขึ้น" ที่สาย pc เคยจะทำแล้วถูกตัด**

**⚠️ ทำไม Good ×1.5 ไม่ใช่ ×2:** `centerMax` = 0.80 → ขอบขวาสุด (1.0) ห่างจากกึ่งกลางโซน 0.20
ถ้า Good ×2 = 0.22 > 0.20 → **เข็มชนขอบขวาก็ได้ Good ฟรี** ไม่ต้องเล็ง · ที่ ×1.5 = 0.165 < 0.20 ยังพลาดได้จริง
(โค้ดมี `math.min(..., 0.19)` clamp ซ้ำอีกชั้นกันคนปรับ Config แล้วลืมข้อนี้ · มีเทสคุมใน `tests/RunTests.luau`)

คลิกถ่ายสำเร็จ 1 ครั้ง มีโอกาส **10%** (`chance`, ปรับจาก 2% โดย user 11 ส.ค.) เจอ skill-check แบบ Dead by Daylight บน **แถบเส้นแนวนอนล่างจอ**: เข็ม**วิ่งกลับไปมา (ping-pong) อิสระไม่หยุด** (ชนขอบ = สลับทิศเอง เป็นแค่ physics ไม่นับอะไร) ผ่านโซน **Good (กว้าง)** + **Perfect (แคบ กลางโซน Good)** ที่กึ่งกลางสุ่มครั้งเดียวตอนเริ่ม (คงที่ตลอด — เข็มวิ่งผ่านเป้าเดิมซ้ำๆ) — ผู้เล่นต้อง **กด N ครั้ง** (สุ่ม **1-5** ต่อ QTE — `hitsMin`/`hitsMax`, **ไม่เกี่ยวกับจำนวน bounce ของเข็มเลย**) — **PC กด Space · มือถือแตะจอ**
- **กด 1 ครั้ง = เกรดจากตำแหน่งเข็ม ณ ตอนนั้น** (perfect/good/miss ตามระยะห่างจากกึ่งกลางโซน) — เข็มเดินหน้าต่อตามเดิม **ไม่รีเซ็ต ไม่สลับทิศจากการกด** (แยกอิสระจาก physics ของเข็มโดยเจตนา)
- **เล่นจนกดครบ N ครั้งเสมอ ไม่ fail-fast** — กดพลาดได้ 0 แต่ยังนับเป็น 1 ใน N ครั้งเสมอ (ให้โอกาสจนจบ — user lock 10 ส.ค.)
- **ยิ่งกดสำเร็จไปแล้วกี่ครั้ง ยิ่งเร่งไว** (`sweepSecondsStart` 1.2 วิ → เร่งลง `sweepSpeedupPerHit` 0.15 วิ/ครั้งที่กดไปแล้ว จนถึงพื้น `sweepSecondsMin` 0.5 วิ) — ผูกกับจำนวนที่กดไปแล้ว ไม่ใช่เวลาที่ผ่านไปเฉยๆ (ผู้เล่นคุมจังหวะพักได้เอง ไม่ถูกเร่งจากการรอ)
- **⚠️ timeout safety net:** ไม่กดเลยเกิน `timeoutSeconds` (15 วิ) = auto-จบให้ (ที่เหลือนับ miss ทั้งหมด) — กัน `InteractLock` ค้างตลอดไปถ้าเผลอ/ไม่ได้ตั้งใจกด (ตัดสินใจของ agent ไม่ใช่ user request ตรงๆ — ป้องกัน softlock ที่ดีไซน์นี้เปิดช่องไว้)
- **รางวัล = footage bonus สะสม (additive)** เพดานรวม **`rewardMultMax` ×10** ไม่ว่า N เท่าไหร่: ต่อครั้ง **Perfect = `(10/N) × GB/คลิก[กล้อง]`** · **Good = ×0.5 ของ Perfect ต่อครั้ง** (`goodRewardRatio`) · **Miss = 0** — กด Perfect ครบทุกครั้งเสมอ = ได้ ×10 เป๊ะไม่ว่า N จะเป็นเท่าไหร่ (เพดานคงที่ ทำให้ N ไม่ใช่ตัวแปร balance แต่เป็นตัวแปร difficulty/ความสนุกล้วนๆ)
- **ทำไม reward เป็น footage ไม่ใช่เงิน/follower:** footage ถูก cap ด้วย storage อยู่แล้ว → jackpot ×10 แค่เร่งสะสม footage เร็วขึ้น **ไม่กระทบเพดานเงิน ≈1.47 ล้าน** โดยตรง (ต่างจากให้เงิน/follower ตรงๆ ที่ต้อง re-derive ทั้งกรอบ)
- **ระหว่าง QTE ผู้เล่นขยับไม่ได้:** `InteractLock.lock()` ปิด ProximityPrompt (กด E ไม่ได้) + freeze เดิน/กระโดด (WalkSpeed/JumpPower = 0) จนจบทั้งชุด
- **authoritative:** server สุ่ม 10% + จำนวนครั้งที่ต้องกด (`RecordService.pickHitsRequired`) + คิด reward สะสม + cap เอง (RecordService) · เชื่อ **เกรดทั้งชุด** จาก client (singleplayer เหมือน inZone/คะแนน QTE ตัดคลิป) · geometry (ตำแหน่งโซน/ความกว้าง/ความเร็ว) tune อิสระใน Config ไม่มีใน PDF

**ตัด 1 คลิป: เลือกขนาด footage ก่อน (unlock 8 ส.ค. 2569 — เดิม 32 GB คงที่ lock 27 ก.ค.)**
ก่อนเข้ามินิเกม ผู้เล่นเลือกขนาด footage ที่จะตัด (เลือกได้เฉพาะขนาด ≤ footage ที่มี) — footage ไม่พอขนาดเล็กสุด = เปิดมินิเกมไม่ได้ (ไม่เสียใจ ไม่ได้คลิป). ขนาดหักตอน**เริ่ม**ตัด (คงหลัก "ไม่ผูก VidQ")

| ขนาด | reward ×(gb/32) | วง (hits) | วงสูงสุดบนจอ | หด/วง (approach) |
|------|------|------|------|------|
| 8 GB | ×0.25 | 10 | 1 | 1.70s |
| 16 GB| ×0.5  | 14 | 2 | 1.55s |
| **32 GB** | **×1.0 (baseline)** | 20 | 2 | 1.40s |
| 64 GB| ×2.0  | 28 | 3 | 1.20s |
| 128 GB| ×4.0 | 40 | 4 | 1.05s |

(ตาราง = `Config.ClipSizes` + `Formulas.clipSizeMult`. เพิ่มแถว 256/512… ได้ "ไปเรื่อยๆ" · difficulty tune อิสระ, rewardMult = gb/32 proportional ล็อก)

- **reward = follower/เงิน × (gb/32)** — คูณที่ `followerGain` ตอนอัป (เงินตามไปเอง)
- **ยิ่งใหญ่ = QTE โหดขึ้น** (วงบนจอเยอะ + หดเร็ว + วงมาก) แลกกับรางวัลต่อคลิปสูงขึ้น
- **ใจ −20 คงที่ทุกขนาด** → คลิปใหญ่ = คุ้มใจ (−20 ได้ reward ×4) แต่ต้องรอด QTE ยาก · คลิปเล็ก = ปลอดภัยแต่ตัดหลายรอบ ใจหมดเร็วกว่า — **ตัวบาลานซ์คือใจ ไม่ใช่ economy**
- **เพดานเงิน ~1.47M ไม่ขยับ:** money = Σ(follower×rate) ผูกเพดาน follower 1M ตายตัว → คูณ reward = ไปถึง 1M ด้วยคลิปน้อยลง เพดานเท่าเดิม
- **คะแนน QTE normalize 0–200** ก่อนคิด VidQ (hits ต่างกันตามขนาด แต่ VidQ วัด %ความแม่นเสมอ)
> **ทำไมไม่ผูกกับ VidQ:** VidQ รู้ผลหลังตัดจบ (คะแนน QTE) แต่ footage หักตอนเริ่ม — ถ้าคิดทีหลังตามเกรด จะกลายเป็น "ตัดห่วย = ถูก / ตัดดี = แพง" คือลงโทษคนเล่นดี

กล้อง L1 อัด 1 GB/คลิก, L6 = 32 GB/คลิก → ยังเป็นเหตุผลที่ต้องอัปกล้อง (กล้องไม่แตะคุณภาพคลิป) และต้องเดินหาโซน ×1.5–2.5 เพื่อสะสม footage ให้ตัดคลิปใหญ่ได้

## 9.6 Comment ตามเกรดคลิป (lock 21 ก.ค. 2569 — PDF หน้า 8 ล่าง)

**การเกิด:** คลิปมี slot comment ⊖/◎/⊕ อย่างละ 1 ใบ (สูงสุด 3) — แต่ละ slot **ทอยแยกอิสระ** ตามเกรดคลิป (แต้มไม่รวม 100 จงใจ ไม่ออก = เงียบ, คลิปไม่มี comment ไม่แสดง):

| เกรด | ⊖ | ◎ | ⊕ |
|---|---|---|---|
| C | 40% | 25% | 10% |
| B | 40% | 36% | 40% |
| A | 20% | 30% | 40% |
| S | 5% | 40% | 50% |

**การตอบ (mental):** กดใจ — ⊕ +10 / ⊖ −10 (◎ กดใจไม่ได้) | ช้อยตอบ ⊖: ยอมรับปัญหา +10 / ประชด −5 / ด่า −10 | ช้อยตอบ ◎: ยอมรับปัญหา +10 / ประชด −5 | ปล่อยผ่านได้ ไม่มีผล
**UI:** สุ่มลำดับช้อยทุกครั้ง — ห้ามเรียงดี/กลาง/แย่ตายตัว (player จะกดแต่บนสุด)
**นับเข้า ending % (agent เสนอ ยังไม่ lock):** ใจ⊕/ยอมรับ→pos, ประชด→neu, ใจ⊖/ด่า→neg, ปล่อยผ่าน→ไม่นับ

## 9.7 Bank ⊖⊕ — ปรับงบจ่ายรายสัปดาห์ (lock 21 ก.ค. 2569 — PDF หน้า 9 บน)

> ⚠️ **แอป Bank ทั้งแอปซ่อนจนถึงเฟส 2** (§1, lock 12 ส.ค. 2569) — เฟส 1 ปรับงบ ⊖⊕ ไม่ได้เลย ค่าใช้จ่ายรายสัปดาห์เก็บที่ offset เริ่มต้น (0) โดยอัตโนมัติ

⊖⊕ บนการ์ด = เพิ่ม/ลดยอดที่จะจ่ายต่อสัปดาห์ของการ์ดนั้น step ไม่เท่ากัน (step + ผลใจ agent เลือก):

| การ์ด | step | ช่วง (offset) | ผลตอนตัดรอบ 7 วัน |
|---|---|---|---|
| 🍚 ค่าอาหาร | ฿200 | −1 ถึง +3 | จ่ายเพิ่ม: ใจ +2/step / จ่ายลด: ใจ −4/step (กินถูก เจ็บกว่ากินหรูฟื้น) |
| 🏠 ค่าเช่า | ฿500 | −2 ถึง +2 | จ่ายเพิ่ม: ใจ +1/step / จ่ายลด: ใจ −3/step / **offset −2 = จ่ายต่ำกว่าสัญญา นับค้างเช่าทุกรอบแม้มีเงิน** (ทางลัดสู่ Bad End ①) |
| 👥 ค่าพนักงาน | ฿1,000 | 0 ถึง +5 | งบโบนัสทีม — ผลจริงรอระบบพนักงาน (§ staff ยังไม่ design) |

ยอดจ่ายจริง = ฐานตามเฟส (WeeklyExpenses) + offset×step, เน็ตคงที่ปรับไม่ได้. ผลใจเข้าเฉพาะวันตัดรอบ (ฝั่งบวกโดน recovery modifier คูณตามปกติ)

## 9.8 ระบบพนักงาน (StaffService) — lock 21 ก.ค. 2569

> ⚠️ ตัวเลขในภาพ PDF หน้า 9 (speed 18 / quality 50 / salary 20k / 10-20 video per day) = **mock วาดให้เห็น UI** ไม่ใช่ค่าจริง — ตัวเลขข้างล่างนี้ design ใหม่จากสมดุลเกม

### หลักการ
**2 สายต่างกันโดยเจตนา** (PDF หน้า 1): **เพื่อนร่วมทาง** = คุณภาพสูง, ฟรี, มาตามเนื้อเรื่อง, โต exponential | **พนักงานจ้าง** = ปริมาณเยอะ คุณภาพต่ำกว่า เสียเงินเดือน จ้าง/ไล่อิสระ
**คลิปพนักงาน = auto ครบวงจร** (อัด→ตัด→อัปเอง) ได้ follower + เงินเข้าเลย ไม่กิน footage/storage ของ player, **ไม่มี viral, ไม่คูณ mental** (อ่อนกว่าคลิปที่ player เล่นดีเสมอ)
**คลิปพนักงานนับเข้า VidQ% ของ ending ครึ่งเดียว (น้ำหนัก 0.5)** และ**สร้าง comment ปกติ** — ตรงเจตนาเฟส 3 ที่ player เปลี่ยนจาก "อัดคลิป" เป็น "ตอบโต้ผู้ชม" (PDF หน้า 1)

**เงิน/คลิป** = follower ที่ได้ × `MoneyRatePerFollower[เฟส]` (เหมือนคลิป player)

## 9.9 ที่อยู่ / ประตู / Tycoon / เสียง (lock 26 ก.ค. 2569)

### ที่อยู่ = **ปลดล็อกเพิ่ม ไม่ใช่ย้ายทิ้ง**
เฟสขึ้น = **ปลดที่อยู่ใหม่** แต่**กลับไปที่เก่าได้ตลอด** (แมพทั้ง 3 เฟสอยู่ในโลกเดียวกัน เดินไปมาได้)
- `Map_Phase1` (ข้างถนน/สะพานลอย) — เข้าได้ตั้งแต่ต้น
- `Map_Phase2` (ห้องเช่า) — ปลดที่ follower ≥ 10,000

## บทเรียนสำคัญที่ได้จากการออกแบบ

- **ผูก logic กับ milestone ไม่ใช่จำนวนคลิป** — ยืดหยุ่นกว่า ไม่ต้องแก้ทั้งระบบเมื่อ pacing เปลี่ยน
- **Bad End เป็น optional challenge ดีกว่า fail state บังคับ** — เกมเข้าถึงง่ายขึ้นโดยไม่เสีย stakes
  และตัดปัญหาลูกโซ่ (limit คลิป/วัน, บังคับ pacing) ออกได้หมด
- **Roblox ห้ามเนื้อหาความตาย** — reframe เป็นความล้มเหลวเชิงสังคม emotional หนักเท่าเดิม
- **ตัวเลขใน UI = placeholder** อย่ายึดเป็น canon
- **Scope discipline** — ทีม 3 คน / 8 สัปดาห์ ตัดได้ตัดก่อน "งานที่ส่งทันดีกว่างานที่ไม่เสร็จ"
