# 11 — กฎการทำงาน: Studio + GitHub

**ใครต้องอ่าน:** ทั้ง 3 คน + agent ทุกตัว อ่านก่อนแตะอะไรทั้งนั้น
**หลักการเดียวจำให้ขึ้นใจ:** **ของจริงอยู่ใน Roblox Studio — GitHub คือสำเนากันงานหาย** ไม่ใช่ที่ทำงาน

```
ทำงานใน Studio → agent mirror ลง repo → push GitHub
                                             ↓
                            เพื่อน pull → agent อ่าน doc → ทำงานใน Studio ต่อ
```

---

## ส่วนที่ 1 — กฎใน Roblox Studio

### 1.1 ก่อนเริ่มทุกครั้ง

1. เปิด place จาก **Shared with Me** (Team Create) — ห้ามเปิดไฟล์ `.rbxl` ในเครื่องแยกกันเด็ดขาด งานจะแตกเป็นคนละเวอร์ชัน
2. ดูมุมขวาบนว่ามีใครออนไลน์อยู่บ้าง — คนที่ออนไลน์กำลังแก้ของเขาอยู่
3. บอก agent ว่า **"ฉันคือสาย A/B/C"** (docs/10 §1) agent จะได้รู้ขอบเขตตัวเอง
4. ให้ agent **pull สภาพจริงจาก Studio ก่อนเริ่มงาน** (docs/08) ห้ามให้มันเชื่อไฟล์ใน repo อย่างเดียว เพราะเพื่อนอาจแก้ใน Studio ไปแล้ว

### 1.2 กฎเหล็กใน Studio

| กฎ | เหตุผล |
|----|--------|
| **แตะเฉพาะโซนสายตัวเอง** (docs/10 §1) | agent เขียนทับไฟล์กันได้ ไม่มีตัวกัน |
| **ห้ามลบ/แก้ของที่คนอื่นสร้าง** โดยไม่ถามในแชททีมก่อน | Team Create auto-save ตลอด **ไม่มี undo ข้ามคน** ลบแล้วหายจริง |
| **4 ไฟล์กลางแก้ทีละคน** — `Shared.Config`, `Services.GameState`, `Main`, `Tests.RunTests` | ทุกสายต้องเติมของตัวเองลงไฟล์เดียวกัน ชนกันแน่ถ้าไม่คิว |
| **ห้ามเปลี่ยนชื่อ instance ที่มีโค้ดอ้างถึง** (`Interact_*`, `Shared`, `Services`, `Remotes`) | โค้ดหาไม่เจอ = เกมพังทั้งเกม |
| **ห้ามใส่ Script/ProximityPrompt เองในแมพ** วาง Part ชื่อถูกพอ (docs/05 §3) | โค้ดแปะให้ตอน runtime อยู่แล้ว ใส่เองจะซ้อนกัน |
| **ห้ามเอา Toolbox ที่มีตัวละคร/โลโก้/เพลงมีเจ้าของ** | ผิดกติกาแข่ง = **ตกรอบ** ไม่ใช่แค่เสียแต้ม |
| **Play test ทีละคน** นัดในแชทก่อน | world เดียวกัน สองคนกด Play พร้อมกันตีกัน |
| **แก้ Content ModuleScript = แก้แต่ข้อความในเครื่องหมายคำพูด** | ลบ comma/วงเล็บ = ไฟล์พัง เกมไม่โหลด |

### 1.3 จบงานทุกครั้ง

1. **Ctrl+S** (Team Create sync ขึ้นคลาวด์)
2. บอก agent ว่า **"mirror ลง repo แล้ว commit push"** — งานที่ไม่ push = ย้อนกลับไม่ได้ถ้าพัง
3. บอกในแชททีมว่าทำอะไรไป โดยเฉพาะถ้าแตะ 4 ไฟล์กลาง

## ส่วนที่ 2 — กฎ GitHub

repo: https://github.com/BossTheDev2209/Revenge-parent (private)

### 2.1 ครั้งแรกในเครื่องตัวเอง

```bash
git clone https://github.com/BossTheDev2209/Revenge-parent.git
cd Revenge-parent
```
เปิดอ่าน `AGENTS.md` แล้วชี้ agent มาที่โฟลเดอร์นี้

### 2.2 รอบการทำงานปกติ

```bash
git pull            # ← ทุกครั้งก่อนเริ่ม ห้ามลืม
# ...ทำงานใน Studio, agent mirror ลง src/...
git add -A
git commit -m "feat: อธิบายสั้นๆ ว่าทำอะไร"
git push
```

### 2.3 กฎ

| กฎ | เหตุผล |
|----|--------|
| **`git pull` ก่อนเริ่มงานทุกครั้ง** | ไม่งั้น doc ที่อ่านเป็นของเก่า agent ทำงานผิด |
| **push จบทุกก้อนงาน ห้ามค้างข้ามวัน** | โซนไม่ทับกัน = conflict เกิดยากมาก แต่ค้างไว้นานเมื่อไหร่ก็ชนเมื่อนั้น |
| **ทำงานบน `main` ตรงๆ ไม่ต้องแตก branch** | ทีม 3 คน โซนแยกกันชัด branch เพิ่มขั้นตอนเปล่าๆ |
| **ห้าม `git push --force` / `git reset --hard` เด็ดขาด** | ลบงานเพื่อนบนคลาวด์ กู้ยาก |
| **commit message เขียนเป็นคน** เช่น `feat: Manage app จ้าง/ไล่พนักงาน` | 3 อาทิตย์ก่อนส่ง ต้องย้อนหาได้ว่าอะไรพังตอนไหน |
| **ห้าม commit ไฟล์ใหญ่** (`.rbxl`, วิดีโอ, PSD) | repo บวม ทุกคน clone ช้า — ไฟล์พวกนี้ไว้ Google Drive |
| **เจอ conflict = หยุด ถามในแชท** | อย่าเดา ของเพื่อนอาจหายทั้งก้อน |

### 2.4 ถ้า push ไม่ผ่าน (ปฏิเสธเพราะ remote ใหม่กว่า)

```bash
git pull --rebase
git push
```
ถ้าขึ้น conflict → หยุด ถ่ายจอถามในแชท

## ส่วนที่ 3 — สิ่งที่ต้องอยู่ที่ไหน

| ของ | อยู่ที่ | หมายเหตุ |
|-----|--------|----------|
| Script ทุกไฟล์ | **Studio** (mirror ใน `src/`) | แก้ที่ Studio เสมอ อย่าแก้ `src/` แล้วลืม sync |
| บท/ข้อความ/ตัวเลข balance | **Studio** `Shared.Content` / `Shared.Config` | |
| รูป UI | **Studio** — อัปโหลดใน Roblox แล้วเอา id ใส่ `Shared.UIAssets` | ไฟล์ต้นฉบับ .png ไว้ Google Drive |
| แมพ/โมเดล/NPC | **Studio** เท่านั้น | ไม่ mirror ลง repo (geometry ไม่ใช่โค้ด) |
| doc/แผน/กติกา | **repo** `docs/` | agent ทุกตัวอ่านจากตรงนี้ |
| วิดีโอ/สไลด์/ไฟล์ส่ง | **Google Drive** | ห้ามใส่ repo |
