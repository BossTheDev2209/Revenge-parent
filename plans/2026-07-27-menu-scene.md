# แผน — Main Menu แบบฉากจริง (diegetic menu)

**สถานะ:** ✅ โค้ดเสร็จ 27 ก.ค. (เทส 354/354) — **รอบอสปั้นห้อง** ระหว่างนี้เกมใช้เมนูปุ่มลอย (fallback)
**คำตอบที่ได้:** ❓1 = ปั้นห้องใหม่แยก (ค่าแนะนำ) · ❓2 = **ฉากจริง กล้องซูมโปสเตอร์** · ❓3 = **เข้าคอมค่อยวาบ**
**สเปกของที่ต้องปั้น ย้ายไป `docs/05 §3.7` แล้ว** (ที่เดียวกับ convention อื่น จะได้ไม่ต้องเปิด 2 ไฟล์)
**สายที่ถือ:** A · **แทนที่:** `plans/2026-07-19-mainmenu.md` (ของเดิม = เมนูปุ่มลอย ทำไปแล้ว จะถูกทับ)

---

## 1. ไอเดีย

เมนูไม่ใช่ปุ่มลอยบนพื้นดำ แต่เป็น**ห้องจริงในเกม** กล้องบินไปหาของแต่ละชิ้นตามที่กด

| กด | กล้องบินไป | เกิดอะไร |
|----|-----------|----------|
| **เล่นต่อ** | จอคอมในห้อง | ซูมเข้าจอ → **จอสว่างวาบขาว** → ค้าง 2–3 วิ → เข้าเกม |
| **โหลดเซฟ** | สมุดบันทึกบนโต๊ะ | ซูมลงสมุด → เห็น**ลายมือ 4 หน้า** = save 4 ช่อง → เลือก → ซูมเข้าจอ → วาบขาว → เข้าเกม |
| **ตั้งค่า** | (รอตอบข้อ ❓2) | แผงปรับ graphic / เสียง / ภาษา |
| **เครดิต** | (รอตอบข้อ ❓2) | ชื่อทีม |
| **ย้อนกลับ** | กลับมุมตั้งต้น | ทุกหน้ามีปุ่มนี้ |

ข้อดีที่ตรงกับเกณฑ์แข่ง: **ออกแบบฉาก 20pt** ได้เต็มๆ (เมนูเป็นฉากจริงที่เล่าเรื่อง "ห้องเช่าคับแคบ") และ **ความเป็นไทย 20pt** โชว์ตั้งแต่วินาทีแรกก่อนกดเล่นด้วยซ้ำ

## 2. ของที่บอสต้องปั้นใน Studio

ทั้งหมดอยู่ใน **`Workspace.MenuScene`** (Folder เดียว) — **`Anchored ✓` ทุกชิ้น**

### 2.1 วางที่ไหน
**ห่างจากแมพจริงอย่างน้อย 500 studs** (แนะนำยกขึ้นฟ้า เช่น y = 2000) — ห้ามให้เห็นจากในเกม
โค้ดไม่ย้าย/ไม่ลบอะไรในโฟลเดอร์นี้ ปั้นอิสระเต็มที่

### 2.2 Part กล้อง (ตัวเล็ก โปร่งใส `Transparency 1`, `CanCollide ✗`)

กล้องจะ**ทับตำแหน่ง + ทิศที่ Part หันหน้า** เป๊ะๆ — จัดมุมโดยขยับ Part ในวิวพอร์ต ไม่ต้องแตะโค้ด

| ชื่อ | มุมอะไร |
|------|---------|
| `MenuCam_Home` | มุมตั้งต้น เห็นห้องกว้างๆ (มุมนี้คือหน้าแรกที่ผู้เล่นเห็น จัดให้สวยที่สุด) |
| `MenuCam_PC` | จ่อหน้าจอคอม (ปลายทางตอนกดเล่นต่อ) |
| `MenuCam_Book` | ก้มลงมองสมุดบนโต๊ะ ให้เห็นหน้าสมุดเต็มเฟรม |
| `MenuCam_Setting` | มุมของ "ของที่แทนหน้าตั้งค่า" (ข้อ ❓2) |
| `MenuCam_Credit` | มุมของ "ของที่แทนเครดิต" (ข้อ ❓2) |

### 2.3 Part ที่ UI ไปแปะ

| ชื่อ | ขนาด | ใช้ทำอะไร |
|------|------|-----------|
| `MenuScreen_PC` | **4 × 2.6 studs** (เท่ากับ `Interact_pcMonitor`) | จอคอมในเมนู — ตอนวาบขาวคือ Part นี้สว่าง |
| `MenuScreen_Book` | **หน้าสมุดกางออก** แนะนำ 4 × 3 studs | SurfaceGui รายการ save 4 ช่อง เขียนเป็นลายมือ |

หน้าที่ควรหันออก = ด้าน **Front** ทั้งคู่ (โค้ดใช้ `Enum.NormalId.Front`)

### 2.4 ของตกแต่ง
อะไรก็ได้ ไม่ต้องตั้งชื่อ — โต๊ะ เก้าอี้ พัดลม กองเสื้อผ้า จานบะหมี่ ฯลฯ **ยิ่งเล่าเรื่อง "ห้องเช่าคนไม่มีอะไร" ยิ่งดี**
ไฟ: แนะนำ `PointLight` ที่จอคอมดวงเดียว ห้องมืดๆ = ได้อารมณ์ + ทำให้ตอนวาบขาวเด่นสุดๆ

## 3. ฝั่งโค้ด

### 3.1 ไฟล์
- `src/client/UI/MenuUI.luau` — **เขียนใหม่ทั้งไฟล์** (ตัวเดิมเป็นปุ่มลอย)
- ไม่แตะ server เลย — action ที่ใช้มีครบแล้ว (`RequestSlots` / `LoadSlot` / `NewGame` / `FreezeTime`)

### 3.2 State machine (pure — เทสได้ด้วย lune)

```
home ──เล่นต่อ──────────────► launching ──(2.5 วิ)──► เข้าเกม
  │                              ▲
  ├──โหลดเซฟ──► book ──เลือกช่อง─┘
  ├──ตั้งค่า───► setting ──ย้อนกลับ──► home
  └──เครดิต────► credit  ──ย้อนกลับ──► home
```

`MenuUI.camFor(screen)` คืนชื่อ Part กล้องของแต่ละหน้า — เทสตรงๆ ไม่ต้องเปิด Studio

### 3.3 ลำดับตอนเข้าเกม (จังหวะสำคัญ)

| เวลา | เกิดอะไร |
|------|----------|
| 0.0 | ปุ่มหาย · กล้อง tween `Home → MenuCam_PC` **1.2 วิ** (`Quad Out`) |
| 1.2 | ยิง action `LoadSlot` / `NewGame` (โหลดตอนนี้ ผู้เล่นไม่เห็นเพราะกำลังจะวาบ) |
| 1.3 | **แผ่นขาวเต็มจอ fade เข้า 0.35 วิ** + `MenuScreen_PC` เปลี่ยนเป็นขาวเรืองแสง |
| 1.65–**4.0** | ค้างขาว ~2.4 วิ (ระหว่างนี้ย้ายกล้องกลับหาตัวผู้เล่น + ปลด freeze + ทำลาย GUI เมนู) |
| 4.0 | ขาว fade ออก 0.6 วิ → เห็นเกม |

> ค้างขาวคือที่ซ่อนงานหนักทั้งหมด (โหลด save, teleport, สร้าง HUD) — ถ้าเครื่องช้ากว่าที่คิดก็ยังเนียน

### 3.4 เรื่องที่ต้องกันพัง
1. **ตัวละครระหว่างเมนู** — ต้องล็อกไว้ ไม่งั้นผู้เล่นเดินได้ตั้งแต่ยังไม่กดเล่น → `Humanoid.WalkSpeed = 0` + ซ่อนตัว (`Transparency 1` ทุกส่วน) แล้วคืนค่าเมื่อเข้าเกม
2. **ไม่มี `MenuScene` ในแมพ** (เช่นเพื่อนเปิดไฟล์เก่า) → `warn` แล้ว**ตกกลับเป็นเมนูปุ่มลอยแบบเดิม** เกมต้องเข้าได้เสมอ ห้ามค้าง
3. **กด rapid-fire** — กดเล่นต่อรัวๆ ต้องไม่ยิง LoadSlot ซ้ำ (flag `MenuUI.busy`)
4. **กล้องคืนสภาพ** — `CameraType` ต้องกลับเป็น `Custom` ทุกทาง รวมทางที่ error

### 3.5 เทสที่จะเขียน
- `camFor` คืนชื่อ Part ถูกทุกหน้า
- ปุ่ม "เล่นต่อ" เลือก slot ที่ `savedAt` ใหม่สุด
- ช่องว่าง → `NewGame`, ช่องมี save → `LoadSlot`
- format ข้อความในสมุดถูก (วัน / follower / เฟส)
- ไม่มี MenuScene → fallback ไม่ error

## ❓ คำถามที่ต้องตอบก่อนเริ่มเขียนโค้ด

**❓1 — ห้องเมนูใช้ห้องเดียวกับเฟส 1 ไหม**
- **ก. ปั้นใหม่แยก** (แนะนำ) — จัดมุมกล้องได้อิสระ ไม่พังตอนทีมแก้ห้องจริง แลกกับปั้นเพิ่ม
- ข. ใช้ห้องเฟส 1 เลย — ไม่ต้องปั้นซ้ำ แต่มุมกล้องจะผูกกับ layout ห้องจริง ใครขยับของ = เมนูเพี้ยน

**❓2 — ตั้งค่า / เครดิต เป็นฉากจริงด้วยไหม**
- **ก. แผงลอยธรรมดา** (แนะนำ) — กล้องอยู่ที่ Home ขึ้นแผงทับ ไม่ต้องปั้นของเพิ่ม เร็วสุด
- ข. ฉากจริงเหมือนกัน — ตั้งค่า = กล้องบินไปที่รีโมท/สวิตช์ไฟ, เครดิต = โปสเตอร์บนผนัง (สวยกว่า แต่ต้องปั้น + วาง Part เพิ่ม 2 ตัว)

**❓3 — เลือก save จากสมุดแล้วไปไหนต่อ**
- **ก. บินต่อไปที่จอคอมแล้วค่อยวาบขาว** (แนะนำ) — ทุกทางเข้าเกมจบเหมือนกันหมด จำง่าย
- ข. วาบขาวจากหน้าสมุดเลย — เร็วกว่า 1 วิ แต่ทางเข้าเกม 2 แบบไม่เหมือนกัน

ตอบ 3 ข้อนี้แล้วเริ่มได้ทันที (โค้ดฝั่ง agent ไม่ต้องรอห้องเสร็จ — ทำ fallback ไว้ ปั้นห้องเสร็จเมื่อไหร่ก็เสียบได้เลย)
